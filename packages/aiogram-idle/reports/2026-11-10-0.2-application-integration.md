# Idle 0.2 application integration verification

Implemented read-only application session authority, immutable activity
registration, shared coordination and verified application FSM isolation. External
session IDs and immutable absolute expiry bind to idle-owned random generations;
authority outages propagate as unavailable and never trigger application cleanup.
Expired authorization retires work while retaining uncertain operation evidence.

Optional Nav 0.2 remains an extra. Combined installation supports manual router
placement and application presentation. External binding and activity/navigation
projection commit together through one backend, rather than independently
updating two stores. Both libraries remain usable separately.

Redis startup remains strict. Explicit managed-service attestation fills denied
inspection facts without overriding contradictions. Format 1 remains the default
until an operator drains old workers and explicitly activates format 2. Bounded
CAS migration preserves claims, tokens, receipts and unresolved effects. The
administrative CLI defaults to dry-run. Managed shutdown drains idle workers before
aiogram closes shared FSM storage/isolation.

## Published dependency freeze

Removed both temporary local peer sources and candidate CI checkout/injection
paths. The committed lock resolves coordination 0.1.0 and Nav 0.2.0 from PyPI;
installed peers have no direct-url/editable metadata. Base and Redis-only
installations do not install navigation. CI and release artifact checks use
published dependencies, without `--peer` overrides.

The 0.2.0 changelog consumes the feature and bugfix fragments and documents the
shared dependency, session protocol migration and staged storage activation.
